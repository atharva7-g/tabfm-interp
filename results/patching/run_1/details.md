## Sample Input

**Clean Input:**
```
a=0.4967, b=-0.1383, c=0.6477
Expected output (a*b + c): 0.5790
```

**Corrupted Input:**
```
a=0.4967, b=<noise>, c=0.6477
```

## Expected Output

### Console Output
- Model inspection summary (number of hookable modules, SelfAttention modules)
- Layer-by-layer patching results table
- Best layer identification
- Recovery percentage summary

### Metrics per Layer
For each layer (0 to N-1):
- `y_patched`: Model output after patching
- `restoration`: y_patched - y_corrupt
- `recovery_ratio`: restoration / (y_clean - y_corrupt)

### Visualizations
- Restoration plot: Shows y_patched - y_corrupt across layers
- Recovery ratio plot: Shows percentage recovery across layers

## Results Interpretation for This Run

### What This Run Tests
This run specifically tests whether **attention head 0** at each layer is causally important for computing **feature b** (the corrupted column) in the multiplication operation `a * b + c`.

### Expected Findings
- **High recovery** (>50%) at certain layers indicates head 0 is responsible for processing feature b
- **Peak recovery layer** shows where feature b is most actively computed
- **Low recovery** suggests feature b is either:
  - Computed by other attention heads
  - Distributed across multiple heads
  - Not primarily handled by attention mechanisms
